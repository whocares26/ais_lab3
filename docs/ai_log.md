## Шаг 2. Код и данные

### Принятые решения и альтернативы

| Решение | Варианты | Выбор и почему |
|---|---|---|
| Хранение термов в JSON | (а) объект `{"низкая": {...}}`; (б) `nlohmann::ordered_json` — объект с сохранением порядка ключей; (в) массив `[{"name": ...}]` | (в). Обычный `nlohmann::json` сортирует ключи объекта по алфавиту, и порядок «критически_низкая … выше_цели» теряется. `ordered_json` порядок сохранил бы, но тогда весь код загрузки (все `from_json`) пришлось бы переводить на другой тип, отличный от ЛР 1–2, а порядок держался бы на неочевидной детали библиотеки. Массив явно выражает, что порядок важен, и читается обычным `json` |
| Задание термов | значения в узлах; параметры tri/trap; оба | Оба: `tri`, `trap` — параметры (программа считает сетку сама), `points` — значения в узлах (пример лекции) |
| Неравномерный универсум | только min/max/step; ещё и список точек | Добавлен `"universe": {"points": [...]}` — без этого не задать X = {800, 830, 860, 900} из лекции |
| x1 в п. 2 и п. 3 | одна переменная с 10 термами; две переменные | Две: `доля_достижения_активации` (7 tri, п. 2) и `доля_достижения_активации_3` (3 терма, п. 3) — у систем разные терм-множества |
| Начало агрегации | нулевой вектор; первый выход; нейтральный элемент | Нейтральный элемент (0 для max и сумм, 1 для min): с нулём min обнулил бы всё, а нейтральный элемент корректен и при пустом списке правил |
| Сравнение a ≤ b у Гёделя | точное `<=`; с допуском | `a <= b + 1e-12`: по определению равенство даёт 1, допуск защищает от погрешности double (см. шаг 3) |
| Чёткий вход в алг. 1–2 | синглтон в ближайшем узле; интерполяция матрицы | Ближайший узел с предупреждением в протоколе — синглтон определён только на сетке |
| Скрытые правила в протоколе | печатать всё; только α_i > 0 | Матрицы — только для α_i > 0 с пометкой «в агрегации участвуют». Выходы B′_i — все, кроме тождественно равных нейтральному элементу агрегации, с пометкой, какие скрыты и почему. Так у логических импликаций видно, что правило с α_i = 0 даёт не 0, а постоянный уровень max A′ |
| Модуль графиков | библиотека; свой генератор SVG | Свой (SvgPlot.cpp, ~350 строк): сторонние библиотеки запрещены, а графики — часть ПО |
| Перезагрузка базы в меню | новый объект; присваивание в тот же | `*knowledgeBase = loaded`: Inference хранит ссылку на базу, ссылка остаётся действительной |

## Шаг 3. Самопроверка

Первый прогон: 34 из 36. Расхождение у Гёделя (Agg = min), п. 2: алг. 1 — 3,316 вместо 3,24; алг. 2 — 3,700 вместо 3,72.

Разбор (без изменения формул):
1. Независимый пересчёт на Python дал те же 3,316 и 3,700.
2. Гипотеза «агрегировались только сработавшие правила» не подтвердилась (тот же результат).
3. Перебор трактовок равенства a = b (при 0, 0,5 и 1): 3,24 / 3,72 получаются ровно тогда, когда
   I(0,5; 0,5) вычисляется как 0,5 вместо 1. Первоначальная гипотеза ИИ — «след погрешности double» — оказалась
   неточной (см. шаг 8).
4. Решение: формула оставлена по определению (a ≤ b ⇒ 1), эталон в самопроверке — 3,316 / 3,700 / пустое.

**Причина (установлена студентом при проверке):** контрольные значения для Гёделя, полученные от ИИ, содержали
ошибку — в проверочном скрипте к знаменателю треугольной функции принадлежности было прибавлено 1e-12. Из-за этого
0,5 становилось 0,4999999999998 на входе и 0,4999999999995 на выходе, и в точке разрыва Гёделя сравнение a ≤ b
ложно давало «нет». Ошибку обнаружила самопроверка программы. Адаптация: эталон пересчитан точно (дробями:
63/19 ≈ 3,316, 37/10 = 3,700, алг. 3 — B′ пустое), формулы программы не менялись.

После исправления эталона: 36 из 36.

## Шаг 7. Доработка после сравнения с программой одногруппника

- `Inference::nearestTerm`, `Inference::conclusion` — после y* выводится терм выхода с наибольшей μ в точке y*
  (по параметрам терма) и соседний терм; строка «ЗАКЛЮЧЕНИЕ: приоритет_доработки — …»;
- колонка «Ближайший терм» в сравнении для нескольких входов, таблица «Словесный итог» в results.md/csv.

Найдено при проверке: у Ларсена (три входа) y* = 4,5 — ровно граница термов «повышенный» и «высокий», μ = 0,5 у обоих;

округлённому y*; выводить оба. Выбрано «выводить оба» с пометкой «на границе термов» — честно отражает результат.

Содержательный вывод для п. 4: конъюнктивные импликации дают итог «повышенный», логические — «средний»
